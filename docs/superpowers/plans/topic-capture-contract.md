# Read-only MQTT topic capture — CR-F10 / E06

This supplements the review2 importer. Capture discovers actual topics and their latest sample through the connection's enrolled Edge. It does not import resources, create mappings, change a connection, publish MQTT, or enroll an Edge.

- Admin `POST /api/v1/connections/{id}/topic-captures`: `{topic_filter, duration_s: 2..30}`. Filter must be equal to or narrower than one configured filter. MQTT only, enrolled Edge, non-archived connection. One pending/running capture per Edge; concurrent requests return `CAPTURE_BUSY`. Response 202 is a job acknowledgment, not discovery success.
- Admin `GET /api/v1/topic-captures/{id}` returns tenant-owned state and, on COMPLETED only, actual samples/counters. `POST .../{id}/cancel` is idempotent, clears partial results and cannot turn a completed capture into cancelled. Capture contains connection UUID/version, a 60-second queue deadline plus the bounded capture window, and explicit error codes.
- Edge `GET /api/v1/edge-sync/topic-captures` claims at most one pending job for that authenticated Edge. Config/secret reference are sent only on this credential-authenticated boundary. Status polling at `.../{id}` detects cancellation/version changes/expiry. `POST .../{id}` completes only a running, unexpired job owned by that Edge; exact acknowledgment retries are safe. Late/cross-owner writes are rejected.
- Lifecycle: PENDING -> RUNNING -> COMPLETED or FAILED; PENDING/RUNNING -> CANCELLED. Expired/config-changed/archived/revoked jobs become FAILED with a reason. Terminal rows are transient and expire after 24 hours; completed payloads are not telemetry history. One active database slot per Edge prevents unbounded queued work.
- Edge uses a unique temporary client ID, clean session and zero session expiry. Normal acquisition and heartbeat continue. Dedicated worker owns subscriber cleanup; cancellation signals it and shutdown joins it. Capture never reuses the live collector client or its inbox.
- Bounds: 2,000 distinct topics, 64 KiB per sample, 1 MiB encoded result. A bounded latest-per-topic map replaces prior samples. Overflow is explicit (`truncated` and counters); topics with oversized/non-JSON samples remain discoverable with sample omitted and reason. Stop or failure always closes the temporary subscriber. Empty capture is TIMEOUT, never fabricated success.
- UI: connection/filter/duration/status/cancel/retry, actual count and errors; edit namespace skip/level types/data suffixes, preview generated hierarchy while preserving raw topics; use existing server import preview/hash/commit. Closing UI cancels active capture best effort; server expiry bounds lost clients.
- Verification: disposable-Postgres ownership, filter limits, concurrency, expiry, connection-version drift, cancellation/late results and acknowledgment retry; controlled real MQTT unique client/read-only/cleanup/bounds; concurrent heartbeat while capturing; actual CUA 36-topic lab capture -> 16 model proposals. All are required before closing E06/CR-F10.
